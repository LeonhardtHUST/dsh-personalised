# dsh-personalised 用户手册

本手册讲怎么用。设计细节见 [DESIGN.md](personalised/DESIGN.md)，安装和迁移见 [README](../README.zh-CN.md)。

## 1. 入口

设置 → 个性化。页面有五个标签页：指令、记忆、导入、导出、分层。原有的记忆面板仍在左侧栏底部的「记忆」按钮里。

所有设置改动先在页面里编辑，再用保存栏提交。只有注入面、工具清单这类改动需要重启 DSH，其余下一轮对话生效。

## 2. 五个标签页

### 2.1 指令

- 开关：关闭后自定义指令整段消失。
- 编辑框：写你的 system instructions，上限 20000 字符。底部显示字数和估算 token。
- 位置：前缀放在人格设定之后、策略段之前；后缀放在工具与策略段之后。想让指令优先级更高选前缀。
- 子代理：勾选后子代理也收到这段指令。
- DSH 原生 AGENTS.md：折叠编辑器，读写 `$DSH_HOME/AGENTS.md`。这是 DSH 自己的机制，会话首轮以 system-reminder 注入。保存时如果文件在别处被改过会提示冲突，刷新后再改。

指令内容不变时，每次请求渲染出的文本逐字节一致，前缀缓存不会因它失效。所以不要在指令里写日期、计数这类每天变的内容。

### 2.2 记忆

画像库的管理页。条目按九类分组：指令、身份、技能、环境、项目、目标、偏好、纠错、待确认。

- 作用域筛选：全局、当前工作区、全部。
- 搜索框按文本过滤。
- 每条可以编辑、删除、置顶，也可以手动新增。
- 置顶条目无视相关度阈值，每次都注入，但仍占预算。
- 待确认条目不会注入。确认后改成其他分类才会生效。

每条有优先级（高/中/低）、证据（明示/归纳/待确认）、时间和状态。其中「指令」和「纠错」两类里，全局、非低优先级的条目进入全局指令层；低优先级的指令和项目作用域的指令按相关度注入。

### 2.3 导入

四步：

1. 点「复制导出提示词」，粘贴给你以前用的 AI 平台。
2. 把它返回的档案粘贴进来，或上传文件。外层的代码块会自动去掉。
3. 选处理方式和目标工作区。「模型处理」用大模型整理、去重、判断冲突；「本地解析」只按格式切分，不联网。模型输出不是合法 JSON 时自动退回本地解析，并给出提示。
4. 预览。每条带徽标：add（新增）、merge（与已有条目合并）、conflict（与已有条目冲突）、skip（跳过）。可以逐条勾选、改文本，然后提交。

提交后页面显示「撤销本次导入」，点一下恢复到提交前的状态。备份在 `~/.dsh/memory/personal/backups/`，保留最近 20 份。

要点：

- 预览只存在内存里，30 分钟过期。过期后提交会失败，重新预览即可。
- 没有绑定工作区时，项目作用域的条目会降级为全局，并给出警告。
- 模型处理需要选模型。没选时依次取设置里的导入模型、子代理模型；都没有就提示你选一个。
- 档案里的「完整性声明」和「待核实事项」不会变成条目，只出现在报告里。

档案格式：

```
### 1. 指令与行为规则
[高][明示][长期有效] 内容
[中][归纳][事件:2026-10-15][进行中] 内容
```

分类标题按序号或关键词匹配九类。没有标签的列表行按所在分类导入，优先级中、证据归纳。

### 2.4 导出

选格式（Markdown 或 JSON）和范围（全部、全局、某工作区），预览后复制或下载。Markdown 按九类输出，开头一行注明来源和时间，结尾带完整性声明。项目条目在内容前加 `〔项目:路径〕`。导出的 Markdown 可以直接导回本插件，或交给别的平台。

### 2.5 分层

控制个人记忆怎么进入上下文。

| 配置键 | 默认 | 含义 |
|---|---|---|
| `personalInjectMode` | `relevant` | 个人和项目记忆的注入方式。`off` 表示不注入 |
| `personalTopK` | 8 | 每轮最多注入几条，1 到 30 |
| `personalBudgetChars` | 1600 | 个人和项目记忆块的字符预算，200 到 8000 |
| `personalSubagentPolicy` | `instructions` | 子代理策略，见下节 |
| `userMemoryInjectMode` | `relevant` | 旧版 `MEMORY.md` 的注入方式。`relevant` 按段落相关度截取，`full` 整份注入（旧行为） |

页面下方的「上下文预览」：输入一句话，看三层此刻会注入什么，以及各层字符数。调参数时用它验证。

导入相关的三个键也在这里：`personalImportProvider`、`personalImportModel`（导入用的模型，留空则跟随子代理模型）、`personalImportTimeoutMs`（默认 180000，范围 30000 到 600000）。

## 3. 分层与子代理

注入分三层：

| 层 | 内容 | 变化频率 |
|---|---|---|
| 全局指令 | 自定义指令，加全局指令类条目 | 只在你编辑或导入时变 |
| 个人记忆 | 事实类条目，取与最新消息最相关的前 K 条 | 每个用户回合重算，结果不变则文本不变 |
| 项目记忆 | 作用域为当前工作区的条目 | 同上，只在对应工作区出现 |

子代理策略 `personalSubagentPolicy`：

- `instructions`（默认）：只给全局指令层，并且要求 `customInstructionsSubagents` 为开。不给个人和项目记忆。
- `none`：什么都不给。
- `all`：三层都给，项目记忆按子代理自己的工作目录判定。

本插件自己启动的后台子代理（自动沉淀、总结等）一律不注入个人和项目记忆。子代理调用 `memory_profile` 只能搜索，不能增删改。

指令相关配置：

| 配置键 | 默认 | 含义 |
|---|---|---|
| `customInstructionsEnabled` | 开 | 全局指令层总开关 |
| `customInstructions` | 空 | 指令正文，上限 20000 字符 |
| `customInstructionsPosition` | `prefix` | `prefix` 或 `suffix` |
| `customInstructionsSubagents` | 开 | 子代理是否收到全局指令 |

## 4. AI 可用的画像工具

`memory_profile`：搜索、新增、更新、删除画像条目。AI 新增的条目标记为来源 agent、证据明示。作用域选项目时，绑定当前会话的工作区。

## 5. 原有记忆功能

以下来自 dsh-auto-memory 引擎，行为未改。配置键和旧版相同，下面只列要点。

### 5.1 自动沉淀

每轮对话结束后，子代理评估这一轮有没有长期价值，有就按主题写进今日日志。不需要说「记一下」。

- `autoConsolidate`：总开关，默认开。
- `autoConsolidateMinChars`：本轮字符数低于它视为寒暄，默认 240。
- `autoConsolidateCooldownMinutes`：两次沉淀最短间隔，默认 30，夜间翻倍。填 0 会回退成 30，不是关闭。
- `autoConsolidateDailyMax`：每日额度，默认 8，计数落盘，重启不清零。

### 5.2 记忆窗口与注入预算

每轮注入的 `<memory_system>` 块，`injectEnabled` 控制开关，`injectBudgetChars`（默认 1600）控制总预算。觉得 AI 总被记忆干扰就调小，想不起事就调大。外部 AI 工具记忆另有预算 `externalInjectionChars`（默认 1400）。凭据和密钥段永远不进提示词。

### 5.3 检索

`memory_recall` 走多路融合：词法（关键词、BM25）永远可用，错误码、变量名靠它命中；语义（向量相似度）召回措辞不同但主题相关的记忆；时间臂解析「昨天」「上周」这类表达并提升该时段的条目；证据加权让被你纠正过的记忆排后。各路用 RRF 合并，默认返回约 93 字符的摘要列表，用 `expand` 或 `memory_read` 取原文。

`semanticEngineMode` 选引擎：`auto`（语义就绪就用，否则词法）、`lexical`、`js`（内置 e5-small，约 130MB）、`python`（BGE-M3，约 563MB）。设置页的检测按钮可以一键体检。不下载模型也能用，只是退化为词法。

### 5.4 记忆中枢

把记忆蒸馏成三层：经历、事实、技能。技能晋升有四道门槛：跨至少 3 个独立会话、成功至少 2 次、被纠正占比不超过 30%、高风险技能需要你手动批准。审批队列在记忆面板的「记忆中枢」页。总开关 `memoryHubEnabled`。

### 5.5 交接白板与自动接续

长任务用 `PLAN.md` 加四段式交接账本记录进度。水位卡显示上下文占用，越过阈值时给出交接建议。接续时选「一键接续」，或在白板页打开「自动接续」。接续时先搜白板：`memory_recall` 的 `scope=handoff`。

### 5.6 外部记忆

接入 WorkBuddy、CodeBuddy、Claude Code、Codex 等工具的记忆文件，逐源扫描、导入或移除。只保存路径指针，不复制内容。

### 5.7 日历、问候与无人值守

AI 从对话里提取截止日期，未完成事项在后续会话持续提醒。暂离超过 `awayMinutes`（默认 60）后回归会收到问候。`unattendedMode` 打开后只注入纯事实记忆，适合批量任务挂机。

### 5.8 记忆工具

AI 可直接调用，你不需要记：`memory_recall`、`memory_read`、`memory_note`、`memory_log`、`memory_user`、`memory_reflect`、`memory_consolidate`、`memory_maintain`、`memory_status`、`memory_external`、`calendar_add/list/done/remove`，以及新增的 `memory_profile`。写入类工具过写入口闸门：乱码、重复行、base64 残留会被拒收并说明原因。

## 6. 数据位置

| 内容 | 路径 |
|---|---|
| 插件配置 | `~/.dsh/dsh-personalised.json`（首次启动从旧配置迁移） |
| 画像库 | `~/.dsh/memory/personal/profile.json` |
| 导入备份 | `~/.dsh/memory/personal/backups/` |
| 用户级记忆 | `~/.dsh/memory/MEMORY.md` |
| 工作区记忆 | `~/.dsh/memory/workspaces/<工作区>/` |
| 记忆中枢 | `~/.dsh/memory/hub/` |
| 证据事件 | `~/.dsh/memory/evidence/events/` |
| 诊断日志 | `~/.dsh/dsh-personalised-diagnose.log`（与 `memory/` 同级） |

设置了 `DSH_HOME` 时，以实际的宿主数据根为准。配置自动复制迁移，记忆目录不搬动。升级、换机和回退前阅读 [迁移指南](MIGRATION.md)；npm `1.0.0` 仍采用旧配置路径，这里的新路径适用于包含本次更新的版本。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| 指令没生效 | 确认「指令」页开关已开、已保存；子代理里没生效，检查「子代理」勾选和 `personalSubagentPolicy` |
| 个人记忆没注入 | 看「上下文预览」；条目是否是待确认；`personalInjectMode` 是否为 `off`；调大 `personalTopK` 或预算 |
| 导入提示请选择模型 | 在导入页选模型，或在设置里配置导入模型或子代理模型 |
| 提交导入返回过期 | 预览超过 30 分钟，重新预览 |
| 导错了 | 导入页点「撤销本次导入」；已离开页面，可从备份目录手动恢复 |
| 设置改了没生效 | 保存栏是否点了；标「重启生效」的项要重启；浏览器端更新后 Ctrl+Shift+R |
| 语义检索为空 | 设置页检测引擎，缺资产按引导下载；auto 档会自动落到词法 |
| 想反馈问题 | 带上诊断日志，到 [issues](https://github.com/LeonhardtHUST/dsh-personalised/issues) 提交 |
